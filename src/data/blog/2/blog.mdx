This is a brain dump.

I've been practising some NeetCode recently and I realised I have forgotten the feeling of pride in writing unassisted code 
how I did at university, when I coded on paper.

Now with IDE autocomplete and AI help it costs next to nothing to iterate.

However, NeetCode has made me very aware of [sunk-cost-fallacy](https://thedecisionlab.com/biases/the-sunk-cost-fallacy), 
where it is painful to delete bad code I've invested time into.

The positive side of sentimentality is, coding becomes an art. I have been taking more pride and placing more effort in 
making code pretty.

On a side note, I have noticed a growing velocity addiction in the industry. When test suites pass - that is
refinement complete for a change, even for production environments. I think we should bring back some pride and take
more care in what we ship, how we did before AI tools.

I've heard the argument *"Prettiness rarely delivers business value and it will be mostly agents who deal with this substandard code 
anyway, why bother?"*
